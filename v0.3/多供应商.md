Provider 集成已从"能连上一个模型"升级成 「能力感知 + 多槽位路由 + 视觉检测」的系统：
同一个供应商下可以挂多个模型，槽位空或模型不可用时自动回退到主模型或第一个可用模型
新增视觉能力验证：测试连接时会发一张内置的"含固定短语"PNG（@rio/visual-runtime 生成），让模型读出指定短语来判断视觉是否可用；视觉复核调 analyze_visual 时会拒绝非视觉模型

用户输入：

| 步骤 | 字段 | 说明 |
| --- | --- | --- |
| 添加 Provider | 显示名称 | 随意 |
|  | 协议 | ANTHROPIC_MESSAGES / OPENAI_CHAT_COMPLETIONS / OPENAI_RESPONSES |
|  | 接口地址 | 厂商提供的地址 |
|  | 上游 API Key | 厂商 Key |
| 添加 Model | 模型名 / 上下文窗口（1024–10M，默认256k）/ 最大输出 token（64–1M）/ 视觉能力勾选 | 能力默认按模型名自动推断，也可勾选覆盖 |
| 测试连接 | 一个按钮 | 返回 鉴权 / 文本 / 工具调用 / 视觉 四项结果 |
| 槽位分配 | 主求解 / 反思 / 视觉 / Triage / Manager | 可复用同一模型，none 清空 |
